# AstroCurve 占星方法论审计报告

## 一、当前算法架构评估

### ✅ 已经做得好的（核心优势）

#### 1. 真实天文计算 — 不是假数据
- 使用 `astronomy-engine.js`（VSOP87 行星模型 + ELP 月球模型）
- 精度 ~0.05°（2-3 弧分），对占星而言完全够用
- Placidus 宫位系统数学实现正确（LST → MC → ASC → 9宫插值）
- 逆行检测基于实际速度变化（前后一天经度差值）

#### 2. Vimshottari Dasha 大运系统 — 真正的个人化时间线
- 完整 120 年 9 大运周期
- 基于月亮 Nakshatra（27 星宿）定位起始大运
- 考虑了大运残余量（fractionElapsed 精确到出生时刻）
- 这是**最核心的个人化因素** — 让每个用户的时间线真正不同

#### 3. KLine 算法多层叠加 — 不是简单随机曲线
```
finalScore = 基础 + chartBias + 行星波 + 年龄包络 + 行运事件 + Dasha修正 + Sade Sati
```
- chartBias 基于实际本命相位（三分/六合加分，刑冲减分）
- 行星波使用真实公转周期（木星11.86年、土星29.46年等）
- Dasha 调节权重占信号的 ~50%（凶星大运压制吉行运，吉星大运缓冲凶行运）
- Sade Sati 识别并施加严重惩罚（-15分峰值）

#### 4. 行运计算 — 有分量权重
- 计算外行星（木土天海冥）对本命盘全11个点的行运
- 有行星权重（冥王最重1.3x）、目标权重（太阳最重1.2x）
- 相位效应区分（三分+9、刑-8、合根据行星特性变化）
- 容许度衰减（orb distance decay）

---

### ⚠️ 需要关注的问题

#### 1. 星历表声明 vs 实际使用不一致
- 市场宣传写 "Swiss Ephemeris DE431 (NASA JPL)"
- 实际代码用 `astronomy-engine.js`（Don Cross 开源库）
- 精度结论一样，但声明不一致损害专业信任

**建议**: 统一话术为 "VSOP87/ELP astronomical model, arcsecond-level precision"

#### 2. 年龄包络线（Life Envelope）是最弱环节
```
42岁前plateau → 60岁前decline → 60后持续下降
```
- 这不是基于个人星盘的，是**硬编码的通用曲线**
- 所有人60岁以后都走下坡，与占星无关
- 用户如果比较自己和朋友的曲线，会发现60+区域雷同

**建议**: 用本命盘木星/土星相位强度调节包络斜率，而非一刀切

#### 3. AI Prompt 的专业性问题
- "20 years of real-world experience" → AI 不可能有经验，精明用户会质疑
- "ABSOLUTE CERTAINTY" → 占星不应承诺绝对确定性
- 关系优先策略（lead with relationships）是好的商业决策，但可能限制深度用户

**建议**: 改为 "drawing on classical and modern interpretive traditions" 代替个人经验声明

## 二、"让用户感觉很准" 的核心因素

### 已有的杀手锏（保持并强化）

| 因素 | 现状 | 为什么用户觉得准 |
|------|------|------------------|
| **Dasha 大运时间线** | ✅ 已实现 | 每个人的周期起点不同，预测高低谷时间不同 |
| **行运相位** | ✅ 已实现 | 同龄人在同一年会因本命盘不同而得到不同预测 |
| **Sade Sati** | ✅ 已实现 | 土星过月亮是占星中最被验证的困难期 |
| **本命相位偏差** | ✅ 已实现 | 刑冲多的人基线就低，三分多的人基线就高 |

### 缺失的"准确感"增强器

#### 🥇 最高优先级：事件验证（Birth Time Rectification Lite）
- **不需要完整校时**，只需："你 2020 年是否经历了重大变动？"
- 用户说"是"→ 产品回答"对，那一年冥王星行运刑你的太阳"
- 这种**retroactive validation**（事后验证）是用户产生信任的最强手段
- 实现方式：用现有行运算法检索过去重大行运，匹配到用户确认的年份

#### 🥈 次高优先级：分宫盘 D9 (Navamsa)
- Navamsa 是 Vedic 占星中**仅次于本命盘的最重要盘**
- 显示"灵魂目的"和婚姻/伴侣特质
- 计算很简单：本命行星经度 × 9 mod 360，重新分配星座
- 在 AI reading 中引用 Navamsa 位置 → 用户会觉得"这个产品很专业"

#### 🥉 第三优先级：Yoga 识别
- 只需识别 5-8 个最常见的 Yoga：
  - **Gaja Kesari** (木月合/刑/冲三分 → "你有天生的智慧和领导力")
  - **Budhaditya** (日水同宫 → "你善于表达和分析")
  - **Chandra-Mangal** (月火组合)
  - **Dhana Yoga** (2宫/11宫主与1/5/9宫主关联)
- 每个 Yoga 就是一句解读，但给用户强烈的"这个懂我"的感觉

## 三、算法可靠性总结评分

| 维度 | 评分 | 说明 |
|------|------|------|
| 天文计算精度 | **9/10** | VSOP87 对占星足够精确 |
| 宫位系统正确性 | **8/10** | Placidus 实现正确，可考虑 Whole Sign 选项 |
| Dasha 系统实现 | **8/10** | 正确，但缺少 Antardasha（子大运） |
| KLine 综合算法 | **7/10** | 多层叠加有深度，年龄包络线是弱点 |
| 行运计算 | **7/10** | 权重体系合理，但只算年度强行运，缺月度精度 |
| AI 解读质量 | **6/10** | 内容丰富但 prompt 有专业性硬伤 |
| Vedic 方法深度 | **5/10** | 有 Dasha + Nakshatra，缺 Navamsa + Yoga + Ashtakavarga |
| 用户"准确感" | **6/10** | 有个人化差异，但缺乏验证机制让用户"确认"准确 |

**综合评价**: 算法基础扎实（不是忽悠），但离"让用户觉得很准"还差 3 步：
1. 事件验证机制（最重要）
2. Navamsa 展示 + AI 引用
3. 常见 Yoga 识别
